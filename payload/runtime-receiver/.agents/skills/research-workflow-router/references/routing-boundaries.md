# Research routing boundaries

## Direct specialist versus Router

Let a clear single-stage request trigger its specialist directly. Use the top
Router only for multi-stage sequencing, cross-domain handoffs, or genuine
ambiguity. Do not add the Router merely to restate a decision already made by
the user's explicit Skill invocation.

## Domain delegation

- Delegate market data, factors, predictive Alpha, backtests, attribution, and
  trading-safety sequencing to `quant-workflow-router`.
- Delegate non-market design, power, statistical analysis, diagnostics, and
  scientific-figure sequencing to `stats-experiment-router`.
- Delegate unclear multi-stage Nature-style manuscript and publication work to
  `nature-research-router`.
- Use `math-research-solve` only through explicit invocation for persistent
  long-horizon mathematical research.

A delegated Router owns its child ordering. Do not preload or duplicate all of
its children in the top-level decision. When it is explicit-only, return its
exact `explicit $router-name` gate and `$router-name` next handoff; do not claim
that delegation activated it.

## Retrieval and full text

Selecting `nature-academic-search` identifies a search capability; it does not
grant network or API authority. Follow the active environment's retrieval
policy and report unavailable sources.

Use `nature-reader` for a user-supplied or otherwise lawfully accessible source
artifact. A DOI, metadata record, abstract, or inaccessible publisher page is
not evidence that a complete paper was read. Institutional, credential-gated,
or paywalled acquisition requires an adopted downloader and separate approval.

## Knowledge capture

Use `manage-personal-knowledge` to locate or govern the configured knowledge
root and stable external resources. Use `obsidian-vault-notes` for bounded Vault
retrieval or an authorized note edit. A routing decision never grants broad
Vault access or a write package.

## Innovation and long-horizon work

Do not treat generic brainstorming as a validated innovation workflow. Use an
installed domain executor when one exists. Otherwise return
`CAPABILITY_GAP_GENERAL_INNOVATION_EXECUTOR` and provide a bounded planning
handoff rather than inventing a Skill.

The heuristic research repositories are an experience-governance, evaluation,
research-memory, Pattern Registry, and future Skill-incubator platform. Until a
real `SKILL.md` payload is published and independently accepted, they are not a
selectable runtime child.

## Experience governance

End a substantial research run with a proposed
`research-governance-receipt/v1` only when the user asks for capture or
governance. Keep Case Package, Pattern, staged Skill candidate, canonical
publication, installation, and activation as separate states and approvals.

Use explicit `skill-dev` only after an approved reusable Pattern and Skill
contract exist. Never let a Router modify active Skills, Manager state, presets,
or installed roots.

## Missing dependencies

Before returning a route, verify that every selected specialist or delegated
Router is available in the current receiver. If any required capability is
missing:

1. name the missing Skill or capability;
2. stop the dependent chain;
3. preserve completed upstream artifacts;
4. state the narrowest safe alternative;
5. do not substitute a similarly named development folder.

## Cross-paper synthesis

Use `literature-synthesis` only when it is installed in the current receiver and
the input includes at least two source-grounded artifacts. Do not substitute the
digest-oriented `nature-literature-pipeline`: that Skill monitors, scores, and
formats literature but does not provide the same claim-level comparability and
conflict contract.

Route source discovery to `nature-academic-search` and individual full-paper
processing to `nature-reader`. Stop at an evidence-depth gate when only metadata
or abstracts are available for a requested full-text conclusion.

## Evidence discipline

- Search breadth does not establish correctness.
- Reading does not establish reproducibility.
- Synthesis does not establish causality.
- Proposal quality does not establish feasibility.
- Code or engineering tests do not establish scientific validity.
- Model agreement does not establish truth.
- A research-memory match is a hypothesis source, not current evidence.
- Publication, installation, and runtime discovery are separate receipts.
